# 区域电力系统优化 · 服务接口设计方案

状态：已确认（2026-09-29）。本文档是 FastAPI 服务化的实施依据，覆盖输入设计、任务模型与并发隔离。
输出（结果 JSON / 图像）格式另行设计，不在本文范围。

## 1. 总体流程

前端两次调用，计算异步：

```
① 用户选文件 → POST /api/datasets（multipart，Excel 模版文件）
     服务端：解析 + 校验 + 生成摘要 → 返回 datasetId + configDefaults
     （此时不计算；configDefaults 供前端渲染配置表单）

② 用户点计算 → POST /api/jobs（纯 JSON：datasetId + config）
     服务端：入队 → 返回 jobId

③ 轮询       → GET /api/jobs/{jobId}
     返回 queued / running / solved / failed；solved 时含四项核对
     （变量规模、约束规模、求解状态、目标函数值）

④ 取结果     → GET /api/jobs/{jobId}/results
```

为什么两段式：
1. 求解慢（168h 约 3 分钟），同步 HTTP 必超时，必须异步任务化。
2. 前端表单的默认值必须由服务端给出（前端不写死任何默认值），只有解析完
   Excel 才知道收资值（备用比例、需求响应比例）和该提示的警告。

## 2. 参数分配：Excel 传什么，配置传什么

原则：**Excel 装"这个省有什么机组、什么曲线"（收资数据）；配置装"收资没收、只能假设的部分"（全部带默认值）**。同一类型机组共用一套假设（类型级粒度），因为收资本身没有单机数据，不存在单机差异信息。

### 2.1 Excel 携带（换省 = 换文件，23 个 sheet）

| 类别 | 内容 |
| --- | --- |
| 负荷 | 最大负荷、用电量、8760 小时负荷曲线 |
| 备用 | 旋转备用 10%、停机备用 5%（周峰比例） |
| 需求响应 | 转移型 2.5%、削减型 2.5%（周峰比例） |
| 煤电 | 每台：容量、最小出力率、受阻率、逐日检修标记 |
| 气电 | 容量、最小出力率、受阻率、工作模式、非运行周 |
| 核电 | 容量、非运行周（无最小出力列——已知收资缺口，按基荷处理） |
| 生物质 | 容量、最小出力率、受阻率、非运行周 |
| 抽水蓄能 | 容量、转换效率、抽水时长、非运行周 |
| 常规水电 | 容量、水库调节系数、月出力曲线（预想/平均/强迫 × 2 水文年） |
| 风电/光伏 | 各电站容量 + 8760 出力曲线 |
| 新型储能 | 容量、转换效率、充电时长 |
| 友好电站 | 风/光/储容量 |
| 送电协议 | 通道参数 + 送电曲线（海南空；测试通道不是真实供电能力） |
| 各设备 | 投产时间、状态（用于筛选目标年在场机组） |

### 2.2 配置携带（全部可选，默认 = 已验证基线）

| 组 | 参数（默认值） |
| --- | --- |
| scenario | 起始时间 2030-01-01、时长 168h、水文 平水年、省间互济关、跨区送电关 |
| solver | 时限 1800s、间隙 1% |
| penalties | 失负荷 28000、弃风/光/水 500 元/MWh、碳价 70、SO₂/NOx/烟尘 1000 元/t |
| province | 充裕度 1.15、新能源利用率下限 0、CO₂ 预算 5887 万 t |
| demandResponse | 转移窗口 4h、转移成本 600、削减成本 3000、**失负荷开关 shedMaxRatio=1**、年削减限额 7105 MWh |
| units.coal | 启停 8h、爬坡 0.3/h、成本曲线 .01P²+280P+10CAP、启动 200 元/MW、停机 10、初始开机 |
| units.gas | 启停 3h、爬坡 1.0/h、发电成本 400、启动 50、初始停机 |
| units.nuclear | 最小出力=额定（基荷）、爬坡 0.2/h、发电成本 100 |
| units.biomass | 爬坡 1.0/h、发电成本 400、年等效发电小时 8000 |
| units.hydro | 发电成本 50 |
| units.pumpedStorage / storage / friendlyStation | SOC 0.1/0.9/初值 0.5、自放电 0.0001、功率成本 200000、能量成本 1100000、替换因子 0.8、循环 5000、友好站储能时长 2h |
| units.fom | 各类型固定运维共 10 个值 |
| emission | 煤 94.6 kg/GJ、发电效率 0.38(≥300MW)/0.35、气 0.40392 t/MWh |

备用/需求响应比例默认取 Excel 收资值；类型级参数（如煤电启动成本 200 元/MW）
展开到每台机组（330MW→66000 元），数值按容量不同，规则同类型一份。

### 2.3 取值优先级

```
用户 config 显式传入 > Excel 收资值 > 内置算例假设默认
```

服务端在任务中保存合并后的 effectiveConfig（生效配置快照），供前端展示、留档、复现。

## 3. 接口定义

### POST /api/datasets

请求：multipart/form-data，字段 file。

响应（对齐前端现有渲染格式，样例见"新建 文本文档(1).txt"）：
- datasetId
- dataTreeModels：菜单树，叶子为 {tableName, tableData:{columns[], rows[]}}，
  列名即模版 sheet 列名、值全字符串、8760 曲线逐行内联——前端用现有表格组件直接渲染。
  树只含收资数据且**只读**（用户不改数据；已与前端确认）。
- warnings[]（code+message，如 NUCLEAR_NO_MIN_RATIO、TEST_CHANNEL）
- configDefaults：普通表单用的默认配置对象（已确认配置走表单不走表格）

校验：缺 sheet / 缺列 / 曲线缺时刻 → 拒绝并列出 {sheet, column, message}；
缺失数据不造、不补 0。

### POST /api/jobs

请求：`{"datasetId": "...", "config": {...}}`。config 全字段可选；用户改了几个传几个。

校验：startTime+hours 不越曲线覆盖；水文情景合法枚举；比例 ∈[0,1]；
socMin<socInitial<socMax；成本>0；开省间互济但送电协议无真实数据 → 拒绝。

响应：jobId。

### GET /api/jobs/{jobId} / GET /api/jobs/{jobId}/results

状态 + 四项核对；结果明细（格式另行设计）。

## 4. 任务模型与并发隔离

无共享可变状态，三条规定：

1. **计算严格串行**：一个队列一个后台工作循环，同时只求解一个。
   一次性消灭 Gurobi license 冲突和内存问题，v1 不写任何并发控制。
   将来要并发：换多进程池，每进程独立全局变量与 Gurobi 环境，结构不变。
2. **dataset 不可变**：上传的原始 Excel 存 datasets 目录只读；多个任务可引用
   同一份。任务不修改它，只复制转换到自己的目录。
3. **每任务独立工作目录**：

```
results/jobs/job_20260929_160001_a1/
  分区机组信息表.xlsx      ← 转换器生成（配置注入）
  算例系统参数.xlsx
  运行数据.xlsx
  solution.json           ← 结果、四项核对、effectiveConfig 快照
  gurobi.log
```

目录跟任务生命周期：完成、失败都保留（追溯/排错），清理策略上线后再定。

## 5. 服务端改造路径

关键决定：**接口层新增"模版 → 三份中间表"转换器；reader.py 及以下（model/solve）一行不改**，
已验证的四项锚点链路原样保留。

转换器职责（不只是拆分）：
- 单位换算（万千瓦→MW）
- 机组筛选（投产晚于目标年、容量 0 → 未纳入，记录原因）
- 风电多站容量加权合成、负荷因子×最大负荷
- 煤电逐日检修标记 → 起止日期；其他设备周区间 → 日期展开
- 派生：需求响应时序（比例×周峰）、友好电站时序（曲线×容量）、
  煤电碳排节点（因子×效率）、年度检修日历
- 配置注入：把 config 各字段写入三份表对应列（类型规则按容量展开）

代码调整：
- config.py 的全局常量（T、START_TIME、文件路径）改为随任务传参，
  load_inputs(pathConfig, runConfig) 参数化——消除多任务冲突的唯一代码改动。
- **回归基准**：现有人工三份表即转换器测试基准，
  `convert(数据模版-海南(1).xlsx, 默认config) ≈ 现有三份` 逐 sheet 逐值比对。
  比对范围 = reader.py 与 model/units 实际读取的 sheet 和列；
  说明类 sheet（使用说明/参数说明/字段说明/源机组清单/未纳入机组/年度检修日历）
  服务不生成、不参与比对（模型不读它们）。

实施顺序：① 转换器 + 回归比对 → ② FastAPI 骨架（上传/提交/队列/目录隔离）→ ③ 输出设计。

**② 状态：已完成（2026-09-29）。** `service/` 下新增两文件：
- `tree.py`：模版 → 前端 dataTreeModels 树（结构对齐"新建 文本文档(1).txt"样例：
  21 张表、图标/节点号一致、值全字符串、8760 曲线 365 行内联；只读）
- `app.py`：四端点 + 串行队列单 worker + 目录隔离（datasets/ 与 results/jobs/）。
  方案A落地：调 solver 前直接设 power_opt config 模块属性，power_opt 零源码改动。
  校验：越曲线窗口、水文枚举、比例 [0,1]、soc 顺序、成本>0、无真实送电数据开互济 → 422。

端到端验证（默认 168h、gap 0.1，2.5 分钟）：四项核对与已验证基线逐项一致
（变量 55839/二值 18984、约束 93340 行/265135 非零元 = 基线模型指纹；
OPTIMAL，obj 302084262.20，gap 2.1%——与 gap0.1 基线 8.4%、gap1e-3 基线 296078601.49
为同模型的三个合法 within-gap 解，规模锚点一致证明转换→建模链路与已验证链路相同）。
运行：`service/` 下 `uvicorn app:app --port 8000`（依赖 fastapi/uvicorn/python-multipart
已装入 conda env power_opt；勿用 --reload，会双开 worker 线程）。
证据：`results/jobs/job_20260929_125533_3fee90/`（三份表+solution.json+gurobi 日志）。

**① 状态：已完成（2026-09-29）。** `service/` 下四个文件：
- `parse_template.py`：模版 23 sheet → 结构化数据（缺 sheet/列即报错，不造数）
- `defaults.py`：DEFAULT_CONFIG（= 已验证基线）+ 深合并
- `convert.py`：全部换算/筛选/派生/配置注入规则 → 三份中间表
- `test_convert.py`：回归比对器

回归结果：`convert(数据模版-海南(1).xlsx, 默认config)` vs 人工三份表，
31 个 sheet（含 8760 曲线、需求响应时序、碳排节点、检修计划）逐列逐值
**0 差异**（数值容差 rel 1e-9 / abs 1e-6）。机组数 12/3/5/7/1/1/1/2，
检修 28 条，未纳入 11 台（气电容量0 ×1、投产超2030 ×10），与人工表一致。

（人工表全量地面真值，`dump_ground_truth.py` 导出）。

## 6. v1 明确不做的

1. 单机参数覆盖（unitOverrides）——类型级够用，真有单机数据先扩模版列
2. 检修计划人工调整——收资数据原样使用
3. 并发计算——串行队列
4. 多省特殊逻辑（供暖期季节切换、径流式水电/光热扩模版）——等第二个省的真数据
5. 输出格式——下一轮设计
