# 新旧系统输入输出差异分析

状态：2026-09-29，基于源码与真实请求样例（非推测）。
姊妹篇：`docs/新旧系统参数对比与同步设计.md`（对接问题清单，怎么接）；
本文只答一个问题：**两套系统的输入/输出到底差在哪、旧系统哪些东西当前系统没用上**。

## 0. 两个系统

- **旧系统（时序生产模拟）**：`20260818\算法源代码FastAPI框架`，FastAPI + simulation 包。
  按优先级逐时段排产出力，无优化目标。四个主流程接口：
  `/api/safety-pasa`（安全保供·自动排检修·平水年）、`/api/prediction-pasa`（促进消纳·同）、
  `/api/safety-mode`（安全保供·平/枯水年两阶段）、`/api/prediction-plan`（促进消纳·同）；
  另有 6 个辅助生成接口（§2.5）。
- **当前系统（优化）**：power_opt（MATLAB→Python，Gurobi 成本最优）+ service/（FastAPI 骨架）。
  一次求解一个窗口（默认 168h），检修是输入不是输出，无模式概念。

证据：旧系统真实请求样例 6 份（浙江/江苏 × 平/枯水年 × 安全保供/促进消纳，data/ 目录）、
旧 app.py/simulation 源码、旧输出 res（74 键，嵌在枯水年请求里）、
当前系统 = 收资模版 23 sheet + DEFAULT_CONFIG + reader/model + 结果.json。

## 1. 输入差异

### 1.1 请求结构对照（旧 in_params 23 键 → 当前系统）

| 旧键（样例实测） | 当前对应 | 结论 |
|---|---|---|
| load：8760 MW 绝对值 | 模版 负荷-8760（归一化）×最大负荷 | 用了，口径不同（绝对→因子×基准） |
| dr_rate：单比例（样例=0） | demandResponse 组：转移/削减两比例+窗口+成本+日/年限额 | 用了且增强（一个比例→预算体系） |
| spin_rate（样例 0.04）/ halt_rate（0.02） | 备用表收资（海南 10%/5%）→ 省级约束 | 用了，口径不同：旧逐周备用曲线，新周峰比例约束 |
| received / send：8760 | 送电协议 sheet + 送电曲线（海南空） | 结构在，数据空（仅测试通道） |
| nuclears：{id, capacity, work_time} | 核电表（非运行周→检修计划） | 用了 |
| wind / solar：{output_curve 8760, **capacity 12 月**} | 电站表+出力曲线；装机=常数 | **按月装机未利用** |
| coals：{id, minPower, capacity, adjustPower, work_time} | 煤电表（最小出力率/受阻率） | **周分段 minPower/adjustPower 未利用**（见 1.2） |
| peak_gases / comb_gases / coal_gases（气电三分类） | 气电一种；模版"工作模式"列 | **三分类未利用，工作模式列读了没用** |
| biomasses：{minPower, capacity, adjustPower, work_time} | 生物质表 | 同煤电：周分段未利用 |
| pumpeds：{capacity, hours, transEfficiency, work_time} | 抽水蓄能表 | 用了 |
| batteries | 新型储能表 | 用了 |
| waters：12 月 × 站 {capacity, reservoirAdjustRate, expectPower, avgPower, forcePower} | 水电月参数（预想/平均/强迫 × 平/枯） | 用了，口径一致 |
| w_s_b / w_s_p（风光储/风光抽一体化） | 友好电站表（风光储） | 风光储用了；**风光抽 v1 未实现**（无算例） |
| yth_batteries / yth_pumpeds（样例各 1 台/空） | 同上（友好电站） | 与 w_s_b/w_s_p 疑似新旧字段名并存，语义待确认 |
| order：['1','2','3']（优先顺序） | 无 | 范式差异：旧按人工优先级排产，新按成本优化，天然不需要 |
| security_cap（样例 0） | 无 | **未利用**，语义不明（对接清单遗留 #7） |
| res（两阶段：平水年结果） | 无跨任务状态传递 | **未利用**（见 2.4） |

### 1.2 旧输入参数当前系统未利用（按影响排序）

1. **周分段 minPower / adjustPower**：旧机组最小出力/可调出力按周区间给值
   （`[{start:0, end:53, value:37.8}]`，53 周），可表达季节/供暖期差异；
   当前每台一个常数 Pmin（模版非供暖期口径）。南方省无感，北方省（供暖期）
   是实打实的能力缺口。
2. **风光按月装机**：旧 capacity 是 12 个月值（投产/退役在年内滚动的场景）；
   当前装机全年常数，只按"投产≤目标年末"一刀切筛选。
3. **气电三分类**（启停调峰/联合循环/同火电）：旧系统分开建模；
   当前一种气电，模版"工作模式"列已收资但 convert 未读（v1 已知债务）。
4. **security_cap**：语义不明（对接清单遗留 #7，问原作者）。
5. **供暖期整套口径**（前端树西北样例可见）：供暖期最小技术出力率/供暖期受阻率/
   是否热电/供暖期起止——模版设计时已预留（通用列+非供暖期列），海南无供暖期
   用不上；v1 明确不做季节切换（设计方案 §6.4），北方省需要时再启用。
6. **保安开机**（前端树负荷表列，保安机组容量 MW）：无对应。
7. **点对网外送/受端/是否配套电源**（前端树煤电列）：无对应——涉及送出专项平衡。
8. **检修天数/起始天**（前端树煤电列，旧口径）：当前改用逐日检修标记（粒度更细），
   模版里"检修天数"列已读但 convert 未用（被逐日标记取代，列本身成冗余收资）。
9. **大区/是否有效**（前端树负荷表列）：当前模版无大区层级、状态列承担有效性。
10. 收资缺口（当前已有 warning，非旧系统遗留）：核电最小出力率列缺失（按基荷）、
    风光储转换效率/时长缺失（配置假设兜底）。

### 1.3 当前系统输入有、旧系统没有的

- 机组 30 列技术经济参数：成本曲线（A/B/C）、启停费、爬坡、最小开停机、初值
  （INIT_STATUS/INIT_POWER/INIT_HOURS）、排放因子、碳排节点（6 节点分段线性）。
- 需求响应预算体系：转移窗口/日限额/年限额/三档成本。
- 储能整套：SOC 三参数、自放电、循环寿命、更换系数、功率/容量成本。
- 省级约束：充裕度、新能源利用率下限、CO₂ 预算。
- 分区模型：分区表/省内断面/省间通道（旧系统无分区概念，对接清单 §三）。
- 检修计划精确到日期（旧是 PASA 输出的周序号+天数）。

## 2. 模式差异（旧有、当前无）

### 2.1 两种运行模式

旧 app.py 明确的两模式差异（源码 docstring 原表）：

| 特性 | 安全保供 | 促进消纳 | 当前系统 |
|---|---|---|---|
| 新能源处理 | 统计概率**保证出力**（ensure 曲线） | **功率预测曲线** | 一条收资曲线，无口径切换 |
| 优先级 | 供电安全优先 | 新能源消纳优先 | 成本最优（取向靠罚权重隐式表达） |
| 弃风光处理 | 储能调节后再补偿（两轮） | 一次性精细化 | 优化内生决定（罚 500 元/MWh） |
| 弃电分配 | 无 | 按比例分配水/风/光 | 优化内生决定 |
| 盈亏计算 | 不减旋备曲线 | 减 spin_curve | 无盈亏口径（只有成本目标） |
| 一体电站 | 不拆分 | 风光抽储拆分计算 | 友好电站整体建模（风光储） |

当前系统近似等价物：失负荷罚 28000 vs 弃电罚 500（约 56:1）事实上是"保供优先"的
权重表达；把弃电罚调高/失负荷罚调低可逼近"消纳优先"。差别在于：旧的换模式换的是
**新能源输入口径**（保证出力 vs 预测出力，同一套收资生成两条曲线，res 里
wind_ensure/wind_random 并存），当前系统没有"保证出力"这个输入概念——要接这个模式，
得先定义"从收资曲线怎么算保证出力"。旧算法已核实（new_energy.py:324-350）：
**ensure = min(月×小时典型出力, 实际出力曲线)**——先由曲线统计出月-小时典型矩阵，
按月铺回 8760 再与实际曲线取小（早期按周版本 __calc_ensure_old 已弃用）。

### 2.2 PASA 自动排检修

旧：PASA 接口输出 coals=[{name, capacity, overhaul(检修开始周序号), day(天数)}]，
是旧系统的**输出**；当前：检修是**输入**（模版逐日标记），方向反转。
当前系统无自动排检修能力。对接方案（先调老 PASA 拿检修计划转新输入）见对接清单 §六。

### 2.3 平/枯水年两阶段

旧：safety_mode(res=平水年结果, in_params=枯水年参数) 二次平衡，复用平水年储能 SOC；
prediction_plan 的 res 参数**源码里强制 None（未实现）**。
当前：单次求解单一水文情景（config.hydrology），初值全是常数（INIT_*），
无跨任务状态传递。当前能做"平水年解完→枯水年再解"，但两阶段之间不传状态。

### 2.4 旧系统独有的时间口径

旧：全年 8760 一次算完，备用曲线周级 53 点，检修周序号，SOC 日级 365 点。
当前：任意窗口 T（默认 168h），全逐时，备用/负荷峰值按周峰但输出逐时。

### 2.5 六个辅助生成接口（当前全无对应）

1. `create_annual_load`：日/年特性曲线（含**农历节假日**修正）→ 8760 负荷；
   当前要求收资直接给 8760。
2. `create_water_curve`：装机+丰枯参数 → 水电 12 月出力特性。
3. `create_power_curve`（月度拉平）/ `create_power_flow`（参考负荷分配）→ 送电曲线；
   当前送电曲线要收资给（海南空）。
4. `addoverhaul`：A/B/C 级检修天数自动分配（国家能源局规程）。
5. `communication_section`：交流断面功率分配（多区域互济）。

前端树里"曲线-288（基于288生成8760）"即第 3 条的产物——288 点月典型曲线扩 8760。

## 3. 旧输入 → 当前输出（交叉去向）

| 旧输入 | 当前去向 |
|---|---|
| load 8760 | 输入（模版）+ **输出回显**（positionChart 本地负荷/修正后负荷列） |
| received / send 8760 | 输入（送电协议）+ **输出列**（positionChart 送电曲线，海南补 0） |
| spin_rate / halt_rate | 仍输入 + 新增**输出裕度**（report.hot/coldReserveMarginMW） |
| 新能源容量因子曲线 | 输入 + 输出（P_wind/P_pv/弃电）；旧系统会内部再生成 ensure/random 双口径，当前不会 |
| 检修（旧是 PASA **输出**） | 反转为当前**输入**（逐日标记）——唯一的"旧输出→新输入" |
| waters 三口径 | 输入直用（水电月参数），输出 P_hyd_ror/P_hyd_res/E_hyd_curt |
| work_time 非运行周 | 输入（转检修计划日期区间），不在输出中回显 |

## 4. 输出差异

### 4.1 旧输出 74 键 vs 当前输出（series 29 + report 19 + positionChart 27）

**已对齐**：工作位置图 27 列（positionChart，2026-09-29 ③ 已完成，
列名/列序对齐老版导出件"…工作位置图(平水年)促进消纳-电量.xlsx"，缺项补 0）。

**有对应但口径不同**：

| 旧输出 | 当前 | 差异 |
|---|---|---|
| wind/solar_ensure + random（双口径并存） | P_wind/P_pv（单口径优化值） | 旧双口径是模式副产物，当前无 |
| spin_reserve[53]（周级） | 无周级备用曲线；report 只有最小裕度标量 | 粒度反了：旧周级、新逐时但无周聚合 |
| profit_loss / *_profit（逐时盈亏） | 无（成本是目标函数，不逐时落盘） | 旧"盈亏"含电价口径，新无电价 |
| res_batteries/res_pumpeds[365]（日级 SOC） | E_ps/E_es/E_fr 逐时 T+1 列 | 新更细 |
| water_wp/base/free/surplus（水电分解四条） | P_hyd_res + E_hyd_curt（月度弃水） | 旧的"工作位置/空闲/弃水"分解无对应 |
| coal_required（煤电总需求） | 逐机组 P_th/u_th（12 台） | 新更细，但无"需求-供给"两条曲线的缺口叙述 |
| max_time / min_time | 无 | 负荷极值时刻 |
| n_p_s / s_p_s / w_p_s | 无 | 语义待确认（疑为份额） |
| w_s_*（一体化拆分：风/光/弃电/容量因子共 11 条） | P_fr_* 四件套 + E_fr | 大体对应，旧的容量因子（_cf）与弃电（w_s_abandon）无 |

**旧有、当前完全无对应**：peak_gas_free / coal_gas_free / biomass_free（周级空闲
机组清单，53×n 二维）、comb_gas_* / coal_gas_* 系列（气电分类明细）、
pumped_comsum / battery_comsum / water_adjust（部分样例为 null，能力存疑）、
dr（需求响应削减——当前有更细的三件套，此项算增强不算缺）。

**当前有、旧没有**：逐机组出力+开停机（u_th/u_gas）、成本分解（燃料/启停/FOM/碳排）、
碳排总量与节点、SO₂/NOx/烟尘、需求响应转出/转入/削减三件套、逐时 SOC、
指标包（利用率/ENS/缺电小时/最大缺口/平衡残差/约束最小残差/MIPGap）、
分区口径结果、四项核对。

### 4.2 结构差异

旧 res：74 键平铺，曲线裸数组（无时间轴、无标签、无单位），消费方要自己知道哪条是什么。
当前：meta（T/起止/水文）+ report（19 指标）+ time（时间轴）+ labels（曲线中文名）
+ series（{keys, data}，keys 是机组/分区标签）——自带元数据。
另外当前 solution.json 外层还带 fourItems（四项核对）/effectiveConfig（配置快照）
/convertSummary（纳入机组数/检修/未纳入清单），旧系统无对应（旧的成功与否只有
success 布尔 + message）。

## 5. 结论与待谈项

差异里真正要上会的是四件（其余按对接清单 §六-七 走）：

1. **模式**：促进消纳/安全保供怎么接。对接清单 §七 已有方案（换曲线口径+罚权重组），
   本文补充的关键事实：旧模式的输入差异是"同一收资生成 ensure/random 两条曲线"，
   当前系统要接，先补"保证出力"的生成规则（旧算法在 new_energy.py 可参考）。
2. **两阶段状态传递**：当前无机制；若业务要"平水年→枯水年连续算"，需要给 config
   加"承接上一任务 SOC/开停状态"的入口（对接清单遗留：与储能首末相等约束的兼容）。
3. **周分段参数与按月装机**：南方省用不上，北方省/投产滚动年是能力缺口，等真实数据。
4. **PASA**：当前不自动排检修，永远先调旧 PASA 或收资给定（已是既定对接方案）。
