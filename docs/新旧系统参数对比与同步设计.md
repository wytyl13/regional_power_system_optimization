# 新旧系统对接问题清单

老系统：时序生产模拟，按优先级逐时段排，输出各类型出力曲线和检修计划。
新系统：Gurobi 优化，逐机组逐小时算成本最小的调度方案。
对接方式：同一套参数先调老系统，再调新系统，结果合并返回。

## 一、参数缺口

新系统每台机组要 30 列参数：成本曲线、启停费、排放因子、爬坡、最小开停时长、初值等。
老请求每台机组只有 5 个字段：编号、容量、最小出力、可调、可用时段。

这 30 列是新系统自己的参数，老请求里没有。要确认一件事：老系统那边（前端表单或数据库）有没有这些参数。
- 有：导出来对接，缺什么列什么。
- 没有：建一张参数台账，按机组逐台补。补的数据源是谁、按容量等级给默认值还是逐台填，要谈。

## 二、机组编号

问题不在格式。老系统编号是数字、新系统是字符串，转一下就行。

问题在同一台机器要认得出来。老请求里每台机的 5 个字段，和台账里那台机的成本、爬坡参数，必须挂在同一台机上。编号错一台，参数就挂错一台。

所以先要确认：两边的编号是不是同一套（从同一张机组表导出来的）。
- 同源：不用建对照表，直接用。
- 不同源：才需要一张对照表。

## 三、分区

新系统的模型建在分区上：负荷表是分区×小时，功率平衡逐区列，断面线路连着区，省级结果是分区结果聚合出来的（MATLAB 995 行，A_province 矩阵把各区加总）。所以省结果依赖分区结果。

但分几个区是数据定的，不是代码写死的（分区表一行就是一个区）。所以只想要省结果时有两条路：

- 路一，有分区数据：按真实分区建（比如 5 个区），能看到断面输送和分区备用。
- 路二，没有分区数据：全省当 1 个区。负荷直接用省级曲线，线路表为空，没有断面约束，等于单母线全省模型。省级结果不受影响（1 个区加总就是全省）。

路二的代价：看不见省内输电瓶颈。
路二要做一次实测：分区表只剩 1 行、线路表为空时模型能不能跑（空表行为之前踩过坑，不能想当然）。

老系统没有分区概念，所以选哪条路是新系统自己的决定，看分区数据拿不拿得到。

## 四、调用顺序

先老后新，四步：

1. 业务请求进来（老 in_params 格式）。
2. 调老系统，拿到老结果：类型级出力曲线 + 检修计划。
3. 适配层把三样东西拼成新系统的输入：原请求 + 老结果 + 参数台账（怎么拼见第六节）。
4. 调新系统，拿新结果，和老结果合并返回（见第五节）。

老系统不改一行代码，只当黑盒调。

## 五、输出合并

合并后的返回分三段：

1. 老结果：原样透传。
2. 新结果：逐机组出力、开停机、成本、排放、图。
3. 并排视图：两边口径一致的量放一起对比——弃电、煤电总出力、缺口、送受电、需求响应量。口径不一致的不放一起（盈亏：老是事后统计、新是优化目标；检修：老是输出、新是输入；逐台机组：新有老没有）。

两个遗留点：
- 老系统备用按周输出，新系统只有逐时，逐时聚到周取最大还是平均要定。
- 两套结果矛盾时（老说够、新算出缺，可能是口径差），编排层并列返回不裁决，裁决规则要成文。

## 六、新系统输入怎么拼（核心）

来源就三块：老请求直接搬的、老结果转的、台账补的。

| 新系统输入 | 来源 | 处理 |
|---|---|---|
| 负荷表（分区×小时） | 老请求 load（8760 省级） | 有分区数据按比例拆区；没有就 1 个区直接用 |
| 机组表（30 列） | 老请求 5 字段 + 台账 25 列 | 老请求给容量、最小出力；台账给成本、爬坡、排放、初值 |
| 检修表 | 老结果 coals（周级检修计划） | 周换成日期（"第 0 周"是哪天要先定） |
| 风光曲线和装机 | 老请求 wind/solar | 拆区或 1 个区；装机按月变化新系统目前是常数，能不能按月变要核 |
| 水电曲线 | 老请求 waters（12 月） | 月值摊到逐时，摊法要定 |
| 储能、抽蓄、一体化 | 老请求 batteries/pumpeds/w_s_*/yth_* | 字段搬过来，缺的台账补；这几轮新系统还没开发完，先记账 |
| 送受电 | 老请求 received/send | 新系统分断面、跨区、互济三种，老的对应哪种要定 |
| 备用参数 | 老请求 spin_rate/halt_rate | 换算成新系统的 adequacyFactor/coldReserveRatio（都是率值乘周负荷峰值，数值对应要逐式核） |
| 需求响应 | 老请求 dr_rate | 一个比例换算成逐区逐时上限加成本曲线，换算式要定 |
| 初值 | 没有来源 | 三选一：冷启动、台账默认、上一阶段结果传下来。要定 |
| 模式参数 | 按老系统的模式选 | 见第七节 |

另有一条规则：老系统缺字段给默认值，新系统缺字段报错。适配层遇到缺的要一次列全报回去，默认值要显式确认才用，不悄悄补。

## 七、模式匹配

核实结果：MATLAB 源码里没有平水年、枯水年、安全保供、促进消纳这些字样。新系统没有模式概念，永远一套模型。

老系统的模式到新系统这里，变成选参数：

| 老系统模式/概念 | 新系统怎么接 |
|---|---|
| 安全保供 | 新能源曲线用保证出力口径、备用取高、失负荷罚高 |
| 促进消纳 | 新能源曲线用预测口径、弃电罚高 |
| 平水年、枯水年 | 两次调用。水文差别就是水电输入曲线不一样。第一阶段末了的状态（储能 SOC、机组开停、功率）传给第二阶段当初值 |
| PASA 自动排检修 | 老输出检修计划直接转新输入检修表（第六节已列） |

两个待办：
- 三处参数（曲线口径、备用、罚权重）的具体数值要和业务定，适配层按模式选组。
- 电池有"首末相等"约束（SOC 末了要等于开始），跨阶段传递初值和这条约不冲突要核一次。

## 八、剩下的要谈项

1. adjustPower 什么意思（爬坡还是可调容量），问原作者。
2. received/send：文档写"12 月协议"、实际是 8760 曲线，以哪个为准。
3. 全年 8760 小时优化的求解耗时，要不要分月滚动调。
4. 水电月值摊逐时的规则。
5. 周输出聚合口径（最大还是平均）。
6. 图用谁的（两套风格不同）。
7. security_cap 什么意思。
8. 部署：端口、鉴权、日志、请求体大小（样例 0.9-8 MB）。
