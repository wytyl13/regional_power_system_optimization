## 模型是什么

- 变量 = 列（出力是连续小数，开停机是二值 0/1）；约束 = 行；非零元 = 表格中非 0 的格子数，决定计算量。
- 指纹（fingerprint）= 整个模型的校验码。两次运行指纹一致 = 模型逐位相同。

## 求解流程（分支定界）

1. **预求解**：先删冗余行列，题变小，答案不变。
2. **放宽版（松弛）**：二值变量暂时允许 [0,1] 小数 → 变成 LP（快且精确）。解出的是**下界**：任何真实方案成本 ≥ 它。
3. **上界**：需要一个**全部**二值变量都是 0/1 的完整方案。启发式（拍板全部 0/1 → 重解连续部分 → 修到合法）快速制造它。固定一部分变量不算，还全是分数呢。
4. **真值被夹死**：`下界 ≤ 真实最优 ≤ 上界`。
5. **停止线**：`gap = (上界 − 最低下界) / 上界 ≤ MIPGap（1%）` 即停。注意比的是全局量：手里最好的方案 vs 未处理分支中最低的下界，不是某一支的成本。
6. **拆树**：gap 超线才拆。挑一个分数变量，按 =0/=1 分两支，各自重解 LP 得新的下界标签。已拆变量永久锁死不回归连续；继续拆 = 再挑一个未定案变量。分支三种结局：不可行剪 / 下界 ≥ 现有方案剪 / 恰好全整数即新方案。

## 日志怎么读（三处关键）

1. **模型身份**（必须跨机器一致）：fingerprint、rows/columns/nonzeros、变量类型、Root relaxation 值、best bound。不一致 = 复现失败，停。
2. **过程噪音**（天然不同，不用管）：迭代步数、各段耗时、预求解删的量、启发式凑到哪个解、最终 gap。
3. **结论区**（最后三行）：

```
Best objective 2.335622731578e+09   ← 找到的方案成本（上界）
best bound  2.335524822265e+09      ← 证明的下界
gap 0.0042%                          ← 真值夹在两者之间，宽度 0.0042%
```

barrier/simplex 迭代长表、crossover 等 = 解单次 LP 的过程记录，整体跳过，直接找 `Root relaxation:` 那行。

# MATLAB → Python 移植策略

## 宏观策略：逐电源递增 + 每步数值比对

- **MATLAB 端零代码修改**。脚本按数据表行数自动生成变量和约束，所以"只留某类电源"通过**重构输入数据副本**实现：复制原 xlsx → 清空其他电源的行 → 同一脚本原样跑。
- **Python 端逐个电源构建**，每加一类电源 = 加一个模块文件，旧模块不动。
- 每一步都用**新做好的适配数据**同时喂 MATLAB 和 Python，比对结果，过了才加下一类电源。
- 插曲规则：跳过"先验证 MATLAB"直接翻译时，该电源记为未验证债务，回头按理论文档补验。

## 每个电源的实施步骤（循环体）

以第 n 轮（已通过前 n-1 类电源）为例：

1. **做数据**：复制原 xlsx，新副本 = 保留前 n-1 类电源 + 贴入第 n 类电源的行，骨架数据（分区表、负荷、系统参数、省级约束、检修计划）始终保留。
2. **跑 MATLAB**：用该副本跑原脚本，四项核对（变量规模、约束规模、求解状态、目标值）进日志；导出结果矩阵为 csv。
3. **写 Python**：新建/启用对应电源模块（读同一份副本），实现输入、决策变量、约束、目标成本。
4. **比对**：变量/约束规模一致、求解状态一致、目标值相对偏差 ≤1e-6、逐时段功率相对偏差 ≤1e-4。
5. **通过 → 回到 1**，加下一类电源。

# 单电源轮次开发协议（2026-09-22 定）

一轮拆成小步，每步做完即停，汇报三件事：本步写了什么、自测数字是多少、与 MATLAB 对照结果如何。自测通过后进入下一步。任何数字对不上，其他工作全部暂停，先查清差异性质——Python 写错 / 数据特性 / MATLAB 源码问题——定性后再继续。

## 一轮分九步

| 步骤 | 这步做什么 | 做完怎么自测 | 停点 |
|---|---|---|---|
| 1 读输入 | reader.py 补这个电源要用的表 | 跑 reader.py，打印行数、装机、常数 | 自测过 → 停 |
| 2 建变量 | 新电源文件：读表 + 建决策变量 | 打印变量总数，和手算公式对 | 自测过 → 停 |
| 3 写约束 | 这个电源的约束，对照 MATLAB 原文一行行写 | 打印约束行数，和手算的账对 | 自测过 → 停 |
| 4 写成本 | 目标函数里这个电源的成本项 | 常数部分单独验算一遍 | 自测过 → 停 |
| 5 拼全模型 | solve.py 把煤电+新电源+系统层拼起来 | 先不求解，数全模型的行/列/非零元 | 对上 → 停 |
| 6 系统层 | context.py 的功率平衡、备用、CO2 等 | 全模型四个数，和 MATLAB log 对 | 对上 → 停 |
| 7 求解 | 跑 Gurobi | 状态是不是 OPTIMAL、目标值和基准差多少 | 打印完 → 停 |
| 8 逐时段对比 | compare.py 和 MATLAB 导出的 csv 比 | 两段式判定（见下） | 打印完 → 停 |
| 9 记坑收尾 | 把这轮踩的坑写回下面那节清单 | — | 写完 → 停 |

## "对上"的标准（模型身份）

两边都是 Gurobi 在跑，log 里直接看得到这些数，不用发明新标准：

- **行数、列数、非零元、0/1 开关变量的个数**：两边 log 里这四个数一样，模型长得就一个样。
- **best bound（log 最后三行里的下界）**：两边逐位一样 = 约束写的是同一个数学式子。这是最硬的证据，别的都对上了它对不上，判失败，不得进入下一步。

## 逐时段对比：两段式判定（2026-09-22 定，起因见煤电轮差异记录第 4 条）

- **硬门槛（不达标即 FAIL）**：目标值相对偏差 ≤1e-6；全网逐小时总出力、开机总台数逐位一致；"手术矩阵"（P_wind/P_pv/弃风/弃光/P_shed/shift_out/shift_in/P_cut 共 8 个）必须全 0——这是"删其他电源删干净了"的证据。
- **软口径（只报不判）**：逐台 u_th/P_th、分区×小时总出力。原因：数据里 172 台机有 171 台能找到参数完全相同的孪生机（330 MW 机组大量复制、跨 5 个区布置），两边求解器在数学等价的方案里各选各的，逐台对齐物理上不可能，聚合口径对齐才是对的。

## 自测期望值的两本账

每个 Python 文件底部带自测代码（`if __name__ == "__main__"`），运行后打印"期望=多少 实际=多少"。期望值两条腿走路，互相当证人：

1. **MATLAB 减法**：MATLAB log 的全模型总数 − 已验证的层 = 这层该有的数；
2. **手推账本**：用公式算，比如煤电约束 132,440 行 = 22 个"机组数×24"块 90,816 + 几个小块（明细写在 thermal.py 注释里）。

两个来源都对上才算过，只对一个不算。

## MIPGap 协议：全程 1e-4（2026-09-23 第三次修订，取消 gap=0 定版）

- 历程：09-22 定"全程 gap=0"→ 09-23 上午改方案 A（开发期 1e-4 + 轮末 gap=0 定版）→ 09-23 下午用户定"全程 1e-4"，gap=0 的 500 秒级树剪证明不再跑。
- **为什么够用**：最优解几秒就找到，gap=0 其余时间全花在剪完整棵树"证明无更优"（气电轮实测 152,745 节点、496 秒）。1e-4 下 6 秒出结果，四项 + best bound 逐位就是数学恒等的硬证据，目标值两侧差实测 ~1e-7。
- **代价与口径**：两侧逐时段解可能停在容差内不同的可行解上（气电轮 1e-4 实测：MATLAB obj 334,534,120.61 vs Python 334,534,256.59，都在 bound 334,534,066.18 之上 1e-4 窗口内）——逐时段按**聚合口径**对账，逐台差异是预期行为不是 bug。气电轮的 gap=0 定版数据（334,534,081.6661）留作历史基准。

## 踩过的坑（每轮收尾把新的补进来；下轮动工前先读这节）

煤电单测不改 MATLAB 代码，靠**删数据**：别的电源行删空、风光容量清 0。于是"0 个机组的电源"是常态，它有几种死法，每轮都要挨个查：

1. **MATLAB 约束带 if 保护的**：0 个机组 → 整块约束跳过。但若这电源的变量还留在目标函数里（系数正、又没约束管它），模型直接无界。早期验抽蓄时踩过（弃水电量），见上文两条经验教训。
2. **MATLAB 约束不带 if 保护的**：0 个机组也照样建行。抽蓄的"同区不能又抽水又发电"，0 台机组时 MATLAB 仍建了 5 区 × 24 小时 = 120 行。漏建时全模型行数差 120 才暴露。
3. **被数据钉成 0 的变量，仍出现在大式子里**。风光容量清 0 → 功率被钉 0，但功率平衡式里 P_wind、P_pv 这两项**永远在**。丢了它们：行数、列数一点不变，只有非零元少 240。**所以行、列全对也可能是错的，非零元必须一起数。**
4. **MATLAB 的 if 有没有，不能凭"合不合理"猜**。需求响应 957-958 行：转移边数为 0 时 MATLAB 仍建约束（效果＝把功率钉 0）；按 Python 编程习惯加 if 跳过的话——T=24 碰巧不出事，T=1 必错。规矩：守卫逐行照 MATLAB 原文抄，不增不删。
5. **四个数全对了还要真求解一次**：形状一样不代表数一样，约束里某个系数抄错，形状不变、解会跑到别的位置。第 7 步省不得。
6. **MATLAB batch 导出必须 value() 包裹**（气电轮连踩两次）：writematrix 只收数值矩阵，sdpvar 直接进去会挂；`*_result` 清单（1154-1182 行）不含 u 矩阵，`u_th_result` 根本不存在（此坑上文的 csv 节其实写过，动工前没重读，重蹈）。batch 命令串里一条语句报错，后面全部不执行（exit 1）。正确写法：`writematrix(value(u_th),'u_th_T24.csv')`。
7. **np.loadtxt 读 T=1 单列 csv 得一维数组**（核生轮）：MATLAB 写出 172×1 的 csv 是纯数字序列，loadtxt 读回 (172,)，与 Python (172,1) 形状断言挂。`ndmin=2` 一行解决。
8. **手推账别心算总和（储能轮踩）**：电储能行数少算 24（MATLAB 820/821 各写在一条拼接里，实际是 `0<=P` 和 `P<=Pmax·u` 两条约束 4 块行，只数了 2 块）；抽蓄非零元逐块加错 400。两处都被"两本账互证"当场抓住。规矩：手推账逐块列清单、逐块按计算器，不脑内加总。
9. **空数组必须 dtype=int（储能轮踩）**：`np.array([])` 默认 float64，拿它当 MVar 的整数索引直接 IndexError。load 函数里所有可能为空的分区/编号数组，建时写死 `dtype=int`。
10. **MATLAB 绘图段 cat(3,...) 不支持稀疏矩阵（储能轮踩，2026-09-24 根因坐实并修复，早先记录有误）**：真根因是 `cat` 沿第 3 维串联稀疏矩阵一律不被支持（`MATLAB:catenate:sparseDimensionBad`），与 T 无关——分区聚合矩阵 A_* 全是 sparse，其乘积保持 sparse 存储，而 `class()` 仍显示 double、size 也正常，逐项 eval 看不出异常。早先"T=24 不崩、疑似 YALMIP 空矩阵求值时序问题"的记录是错的：历轮 T=24 的 csv 实际都是 try-catch 容错导出的。修法（2026-09-24 用户批准）：cat 前全部 `full()` 转稠密 + 含 value() 的六项先算中间变量，纯存储转换数值不变；T=1/T=24 双验证 obj 与储能轮基准逐位一致，证明对模型零影响。
11. **config.DELTA_T 遗留错误值（水电轮踩）**：动工自测发现 config 里 `DELTA_T=24.0`——不是任何一轮基准的合法状态（T=24 轮需 1.0，否则 fixedCostScale 变 657.5 而非 27.397，目标值必挂），疑似上会话遗留。已复位 1.0 并验证 scale=27.3972602740。教训：**每轮动工第一件事跑 reader 自测打印 fixedCostScale**，这个值错了后面全错。
12. **库容水电分时形状是并列最优，不是 bug（水电轮 T=24 踩，2026-09-24 用户裁决：不改 compare）**：周期电量约束给了水电 24 小时内的分时自由度；当两个时段煤电边际成本严格相等（孪生机平台+分段线性平坦段），电量放哪总成本一样 → 无穷多等价解，两侧各停一个顶点。本轮实例：时段 21↔23 互换 21 MW，obj 差 1.4e-13、总量/E_curt/其余物理量全对齐。判定口径维持原样（该数据下 T=24 报 FAIL 属预期），差异记录在轮次章节；**后续凡带周期电量预算的电源（光热同理）都会复现此现象**——DR 轮（数据未变）已原样复现。
13. **matlab -batch 进程残留互抢（DR 轮踩，2026-09-24）**：T=24 的 batch 命令正常返回（打印 CSV_DONE、管道 exit 0），但 MATLAB.exe 没退净；紧接着启动的下一条 T=1 batch 与残留进程互抢（license/资源），先磨 300 秒超时、再报假错 `Exit Status: 0x00000001`（真错误信息被 tail 截断且 gurobi log 未生成，极易误判为建模 bug）。`taskkill //F //IM MATLAB.exe` 清场后同一条命令 22.5 秒跑完。规矩：**每条 matlab -batch 结束后 `tasklist` 确认进程退净，再跑下一条；排障时先清场重跑一次再查代码**。

## Python 侧：变量与核验

### 总纲：两层结构（与 MATLAB 的"一大坨"不同）

- **电源层**（model/units/thermal.py）：只有煤电的 12 个变量。没有气电、核电……的空壳——**Python 不建空壳**。
